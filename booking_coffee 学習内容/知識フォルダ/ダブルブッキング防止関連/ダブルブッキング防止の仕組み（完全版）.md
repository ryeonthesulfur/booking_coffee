# 解説：3時間制の仕組みとダブルブッキング防止ロジック

---

## このカフェの予約ルール

予約は **3時間制**。13:00に予約したら、13:00〜16:00まで席を使う。

---

## 3時間制で「足す」と「引く」、2つの計算がある

同じ「3時間」でも、**誰のための計算か**によって方向が逆になる。

| 計算 | 誰のため | 目的 |
|---|---|---|
| 3時間を**足す** | 予約者 | 「いつまで使えるか」終了時刻を知るため（未来を見る） |
| 3時間を**引く / 足してチェック** | システム | 「この時間帯は空いているか」を過去・未来の予約から調べるため |

ここを混同しやすいので、以下で順を追って解説する。

---

## ① 予約者視点：3時間を「足す」

13:00に予約 → **13:00 + 3時間 = 16:00まで** 席を使う。これは単純な足し算で、未来の占有時間を決めるだけ。

---

## ② システム視点：なぜ前後3時間を調べるのか？

ユーザーが **「15:00から予約したい」** と選んだとき、システムは **「15:00の時点でその席を使っている人がいるか」** を調べる必要がある。

3時間制なので、15:00の時点で「かぶる」予約は**2方向から来る。**

### 過去方向（3時間前〜直前に始まった予約）

12:30に始まった予約の利用時間は12:30〜15:30。15:00にまだ利用中 → **かぶる**。

```
ケース1：14:00開始 → 14:00〜17:00利用 → 15:00にかぶる ❌
ケース2：12:30開始 → 12:30〜15:30利用 → 15:00にかぶる ❌
ケース3：12:00開始 → 12:00〜15:00利用 → 15:00にちょうど終わる → かぶらない ✅
```

### 未来方向（直後〜3時間後に始まる予約）

自分が15:00〜18:00を使うので、その間に始まる予約とも競合する。

```
ケース4：16:00開始 → 16:00〜19:00利用 → 自分の15:00〜18:00とかぶる ❌
ケース5：18:00開始 → 18:00〜21:00利用 → 自分の予約が終わってから始まる → かぶらない ✅
```

### まとめ

**「開始時刻が 12:00〜18:00 の間にある予約 = 15:00の時点で競合する予約」**

```
12:00 = 15:00 - 3時間（過去の境界）
18:00 = 15:00 + 3時間（未来の境界）
```

---

## ③ 実際のコード

```ruby
.where("reservations.start_time > ? AND reservations.start_time < ?",
       start_time - 3.hours,   # = 12:00（この時刻より後）
       start_time + 3.hours)   # = 18:00（この時刻より前）
```

### `>` と `<`（厳密な不等号）を使う理由

| 境界 | 状況 | 判定 | 理由 |
|---|---|---|---|
| 下限 `> 12:00` | ちょうど12:00開始の予約は12:00〜15:00 | かぶらない | 15:00にちょうど終わるので次の人が使える |
| 上限 `< 18:00` | ちょうど18:00開始の予約は18:00〜21:00 | かぶらない | 自分の予約15:00〜18:00が終わってから始まる |

境界ちょうどはどちらもかぶらないので、`>=` `<=` ではなく `>` `<` を使う。

---

## 映画館の例え

あなたは「15:00〜18:00」のスクリーンを使いたい。受付の人は頭の中でこう考える。

> 「12:00より後に始まって、18:00より前に始まった映画は全部かぶっている。そのリストを返せばいい」

これが今回のシステムロジックそのものだ。
