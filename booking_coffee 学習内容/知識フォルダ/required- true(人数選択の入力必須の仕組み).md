# 解説：required: true vs. presence: true (入力必須の仕組み)

このドキュメントは、フォームの項目を「必須入力」にするための2つの方法、`required: true` と `presence: true` の違いと、なぜ両方が重要なのかを解説します。

---

## Q. ドロップダウンの「人数を選択」を選んだまま送信できないようにしたい

`prompt: "人数を選択"` で表示される最初の項目は、あくまで案内役です。
これを選んだままではフォームを送信できないようにするには、「必須入力」の仕組みが必要です。その代表的な方法が `required: true` です。

---

## `required: true` とは？ (ブラウザ側のガードマン)

これは、Railsのフォームヘルパーに追加できるオプションで、生成されるHTMLタグに `required` 属性を追加します。

**例:**
```erb
<%= f.select :num_people,
      (1..@seat.capacity).map { |n| ["#{n}名", n] },
      { prompt: "人数を選択" },
      required: true,  # ← これを追加
      class: "form-input" %>
```

**何が起こるか？**

-   この項目が未選択（"人数を選択" のまま）で送信ボタンを押すと、**ブラウザが送信をブロック**し、「このフィールドを選択してください」といった警告をユーザーに表示します。
-   これは、データがサーバーに送られる**前**に、ブラウザ側でチェックする仕組みです。

---

## `presence: true` とどう違うの？ (サーバー側のガードマン)

`presence: true` は、モデルファイルに書くバリデーション（検証ルール）です。

**動くタイミングが違います。**

-   **`required: true`**: **ブラウザ側**で弾く（データがサーバーに届く前）。ユーザーに即座にフィードバックを与えるUX（ユーザー体験）向上のための機能。
-   **`presence: true`**: **サーバー側**で弾く（データがDBに保存される前）。不正なデータが保存されるのを防ぐセキュリティのための機能。

---

## 結論：両方書くのがベストプラクティス

`required: true` は、JavaScriptが無効になっていたり、悪意のあるリクエストが送られたりすると簡単に突破されてしまいます。そのため、**セキュリティ的に本当に重要なのは、サーバー側で必ずチェックを行う `presence: true`** です。

両方を設定することで、
1.  通常のユーザーには `required: true` で親切な即時フィードバックを提供し、
2.  万が一ブラウザのチェックをすり抜けても `presence: true` で確実にデータを保護する

という、UXとセキュリティを両立した堅牢なフォームを作ることができます。
