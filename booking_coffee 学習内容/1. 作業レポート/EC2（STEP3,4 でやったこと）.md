================================================================
  STEP 3 と STEP 4 の意味と違い
  環境変数の設定 と database.yml の設定
================================================================


================================================================
  まず「なぜこの2つが必要か」
================================================================

RailsアプリがRDS（データベース）に接続するには、以下の情報が必要。

  ・どのサーバーに繋ぐか（RDSのエンドポイント）
  ・どのユーザーで繋ぐか（マスターユーザー名）
  ・パスワードは何か（マスターパスワード）

これらをどこに・どうやって書くかが STEP 3 と STEP 4 の役割。


EC2の中に、本番用のデータベースの鍵とパスワードを保存して、
それをRails アプリ本体のデータベースファイルに反映させて、且つ、どのデータベースサーバーで本番環境をやるのかの名前を「host:」で書く。


                              意味	                            今回で言うと
データベースサーバー	    MySQLが動いているサーバー本体	          RDS（AWSのサービス）
データベース	        その中にある「データの入れ物」	           booking_coffee_production

イメージとしては：

データベースサーバー → 図書館の建物
データベース → その中の本棚のひとつ

RDSという図書館の中に、booking_coffee_production という本棚があって、そこに予約情報やユーザー情報が入っている、という構造です。
host: で指定しているのは図書館の住所（サーバーのアドレス）、database: で指定しているのがその中のどの本棚か、という違いです。

================================================================
  STEP 3：環境変数の設定（/etc/environment）
================================================================

わかりやすく言うと、「パスワードなどの秘密の情報を、コードとは別の、サーバーの中の金庫に保管する」作業です。

■ やったこと
  /etc/environment に以下を書いた：
    RAILS_ENV="production"
    SECRET_KEY_BASE="（長い文字列）"
    BOOKING_COFFEE_DATABASE_PASSWORD="（RDSのパスワード）"

■ 意味
  「機密情報をEC2サーバーの中に保存する」作業。

  パスワードや秘密鍵をコードに直接書くと、
  GitHubにpushしたとき世界中に公開されてしまう。
  それを防ぐために「環境変数」という仕組みを使う。

  環境変数 = サーバーの中にだけ存在する変数。
  コードには書かず、サーバーの設定ファイルに書いておく。
  Railsからは ENV["変数名"] という形で呼び出せる。

■ /etc/environment とは？
  EC2サーバー全体の環境変数を管理するファイル。
  Macの ~/.zshrc に似た概念で、サーバー起動時に自動で読み込まれる。
  sudo が必要なのはサーバー全体の設定ファイルだから。

■ source /etc/environment とは？
  ファイルを書き換えただけでは「次回起動時から」しか反映されない。
  source コマンドで「今すぐここで読み込め」と指示する。
  Mac で source ~/.zshrc をするのと全く同じ概念。

■ SECRET_KEY_BASE とは？
  Railsがセッション情報（ログイン状態など）を暗号化するための秘密鍵。
  本番環境では必須。bundle exec rails secret で生成する。
  これが漏れると、他人がログイン済みのふりをしたセッションを
  偽造できてしまうため、絶対に公開してはいけない。


================================================================
  STEP 4：database.yml の設定
================================================================

わかりやすく言うと、「Railsアプリに対して、本番環境で使うデータベースの住所（どこにあるか）を教える」作業です。

■ やったこと
  config/database.yml の production: セクションに
  host（RDSのエンドポイント）を追加した。

■ 意味
  「Railsに対して、どのデータベースサーバーに繋ぐかを教える」作業。

  database.yml は Railsの「データベース接続設定ファイル」。
  開発環境（Mac）と本番環境（EC2）で接続先が違うため、
  production: のセクションに本番用の設定を書く。

■ なぜhostを追加したか？
  開発環境では host: localhost（自分のMac上のMySQL）だった。
  本番環境では RDSというAWSのデータベースサーバーに繋ぐ必要があるため、
  RDSのエンドポイント（アドレス）を host に指定した。

■ パスワードはなぜ ENV["..."] と書くか？
  password: （パスワードをそのまま書く）← NG
  password: <%= ENV["BOOKING_COFFEE_DATABASE_PASSWORD"] %>  ← OK

  コードに直接パスワードを書くと GitHub に流出する。
  ENV["..."] と書くことで「環境変数から読み込む」という意味になる。
  STEP 3 で /etc/environment に書いた値がここで使われる。

■ YAMLのインデントに注意する理由
  database.yml は YAML という形式で書かれている。
  YAMLはインデント（字下げ）で構造を表現するため、
  ずれると「設定が読み取れない」エラーになる。


================================================================
  STEP 3 と STEP 4 の違いまとめ
================================================================

  STEP 3（/etc/environment）
    → 機密情報（パスワード・秘密鍵）をサーバーに保存する
    → 「値そのもの」を安全な場所に置く

  STEP 4（database.yml）
    → Railsにデータベースの接続先と接続方法を教える
    → 「どこに繋ぐか・どう繋ぐか」の設定

  関係性：
    STEP 4 の database.yml が ENV["BOOKING_COFFEE_DATABASE_PASSWORD"] を参照する
      ↓
    STEP 3 の /etc/environment に書いた値が使われる

  つまり STEP 3 で値を「用意」して、
  STEP 4 でその値を「使う場所」を設定した、という流れ。





================================================================
  補足：Render と AWS EC2 での環境変数の管理の違い
================================================================

【Render の場合】
  Renderのダッシュボード（Web画面）上に「環境変数」の設定画面がある。
  そこにキーと値を入力するだけで、自動的にサーバーに反映される。
  コマンドもファイル編集も不要。GUIで完結する。

【AWS EC2 の場合】
  環境変数を管理する仕組みは自分で用意する必要がある。
  今回は /etc/environment に手動で書いて、source で反映した。
  全て自分でコマンドを打って設定する。

【ローカル（Mac）で開発中の環境変数について】　※Basic認証の場合など
  ~/.zshrc に export DATABASE_PASSWORD="..." と書いておけば
  自分のMacで rails server したときだけ使われる。
  RenderやEC2のサーバーには一切関係ない。
  あくまでMac上のRailsが参照するだけ。

【まとめ】
  Render → GUI上で設定、自動で反映。楽。
  EC2   → 自分で /etc/environment に書いて source で反映。手動。
  Mac   → ~/.zshrc に書く。ローカル開発用。
