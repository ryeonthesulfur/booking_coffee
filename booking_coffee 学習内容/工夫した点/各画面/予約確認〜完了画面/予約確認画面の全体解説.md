# 予約確認画面 (`confirm.html.erb`) の解説

このファイルは、ユーザーが予約内容を最終確認し、予約を確定させるための重要な画面です。
この画面は、大きく3つの要素で構成されています。

1.  **選択した座席のハイライト表示**
2.  **予約を確定するためのフォーム**
3.  **入力内容を修正するためのリンク**

---

## 1. 選択した座席のハイライト表示

ユーザーが前の画面で選択した座席を、間取り図上で視覚的に分かりやすく表示します。

-   **`data-seat-number` 属性**:
    ```erb
    <div id="confirmed-seat" data-seat-number="<%= @seat.seat_number %>"></div>
    ```
    コントローラーから渡された `@seat` の座席番号を、HTMLの `data-seat-number` 属性に埋め込みます。これが、JavaScriptがどの席をハイライトすべきかを知るための「目印」になります。

-   **`confirm_mode: true`**:
    ```erb
    <%= render "stores/kuramae_floor", confirm_mode: true %>
    ```
    間取り図のパーシャル（部品）を呼び出す際に、`confirm_mode: true` という「合言葉」を渡しています。パーシャル側ではこの合言葉を受け取り、「今は確認モードだから、"予約に進む"ボタンは非表示にしよう」といった表示の切り替えを行っています。

---

## 2. 予約確定フォーム (`form_with`)

ユーザーに表示されている情報を、実際にデータベースに保存するためのフォームです。

```erb
<%= form_with model: @reservation, url: store_seat_reservations_path(@store, @seat), ... do |f| %>
```

### `hidden_field` の役割：画面をまたぐ情報のバケツリレー

このフォームの最も重要な点は、`hidden_field` の使い方にあります。

-   **`hidden_field` が必要な情報**: `start_time`, `num_people`, `phone_number`, `notes`
    -   これらはユーザーが前の画面で入力した、**データベースにまだ存在しない情報**です。この確認画面を挟むことで情報が失われないよう、`hidden_field` という「見えない入力欄」に入れて、次の `create` アクションに引き継いでいます。

-   **`hidden_field` が不要な情報**: `予約者名`, `店舗名`, `座席番号`
    -   これらは `hidden_field` に入れていません。なぜなら、サーバー側でより安全かつ確実に取得できるからです。（予約者名: `current_user`、店舗・座席: URLのID）
    -   もしこれらのID情報を `hidden_field` で送ると、悪意のあるユーザーが値を書き換えて「他人になりすます」「別の席を予約する」といった攻撃が可能になってしまいます。

この使い分けは、**「クライアントから送られてくる情報は信用せず、サーバー側で検証・再取得できる情報はそちらを正とする」**という、Webセキュリティの基本原則に基づいています。

---

## 3. 予約修正リンク (`link_to`)

ユーザーが入力内容を修正したい場合に、入力情報を保持したまま前の画面に戻るためのリンクです。

```erb
<%= link_to "予約内容を修正する", new_store_seat_reservation_path(
      @store, @seat.seat_number, 
      start_time: @reservation.start_time.strftime("%Y/%m/%d %H:%M"), 
      ...
) %>
```

-   **クエリパラメータの活用**: `start_time:` や `num_people:` のように**名前付き（キーワード引数）**で値を渡すことで、URLの末尾に `?start_time=...&num_people=...` という**クエリパラメータ**を付けています。

-   **ユーザー体験の向上**: 遷移先の `new` アクションは、このクエリパラメータを受け取って `Reservation` のインスタンスを初期化します。これにより、フォーム画面には先ほどまで入力していた内容が復元された状態で表示され、ユーザーは修正したい箇所だけを直せばよくなります。
