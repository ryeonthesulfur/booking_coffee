# 解説：予約済み座席はどうやって探すの？ - `joins`でテーブルを繋ぐ技術

「この座席はもう予約されているから、クリックできないようにしたい」

この機能を実現するために、`stores_controller.rb` で `@reserved_seat_numbers` という変数を用意しました。

```ruby
# stores_controller.rb

@reserved_seat_numbers = @store.seats
  .joins(:reservations)
  .where(reservations: { status: [:reserved, :using] })
  .pluck(:seat_number)
```

この一行のコードが、どのようにして「予約済みの座席番号リスト」を取得しているのか。
データベースへの「問い合わせ（クエリ）」の流れを、ステップ・バイ・ステップで解き明かしていきましょう。

---

## データベースへの問い合わせ（クエリ）の旅

このコードは、まるで探偵が手がかりを元に犯人を絞り込んでいくような、一連の命令で構成されています。

### 1. `@store.seats` - 捜査の開始地点

-   **命令：「このお店（`@store`）にある、すべての座席（`seats`）をリストアップしてくれ！」**

まず、クエリは `@store.seats` から始まります。これは「今見ている店舗に所属する、すべての座席」をデータベースから取得しようとする最初のステップです。

この時点では、まだどの席が予約されているかは全くわかりません。ただの「座席一覧」があるだけです。

### 2. `.joins(:reservations)` - 関連資料の取り寄せ

-   **命令：「それぞれの座席に、関連する予約記録（`reservations`）をくっつけて見せてくれ！」**

`seats` テーブルだけを見ていても、予約状況はわかりません。なぜなら、予約のステータス（`status`）は `reservations` テーブルに記録されているからです。

`joins` は、この2つのテーブルを内部的に結合（JOIN）する魔法のメソッドです。`Seat` モデルと `Reservation` モデルは `has_many` / `belongs_to` で関連付けられているため、Railsは `seat_id` を使って2つのテーブルを賢く繋げてくれます。

**例えるなら…**
学生名簿（`seats`）だけでは、誰がテストで合格したかはわかりません。
そこで、成績表（`reservations`）を持ってきて、学生名簿の横に並べる作業が `.joins` です。これで初めて、「この学生の成績は…」と確認できるようになります。



### 3. `.where(reservations: { status: [:reserved, :using] })` - 条件による絞り込み

-   **命令：「くっつけた予約記録の中から、ステータスが『予約済み』か『使用中』のものだけを残してくれ！」**

`joins` で関連情報が手に入ったので、いよいよ絞り込みです。
`where` メソッドを使って、「`reservations` テーブルの `status` カラムが `reserved` または `using` になっている座席」だけをフィルタリングします。

これで、捜査対象は「現在、誰かが予約しているか、まさに今使っている座席」だけに絞り込まれました。



### 4. `.pluck(:seat_number)` - 証拠品の特定と収集

-   **命令：「絞り込んだ座席のリストから、『座席番号（`seat_number`）』だけを抜き出して、配列にしてくれ！」**

最後に `pluck` です。今欲しいのは、予約済み座席の「座席番号」のリストだけです。座席の定員や料金といった他の情報は必要ありません。

`pluck` は、指定したカラム（ここでは `:seat_number`）の値だけをデータベースから直接抜き出し、シンプルな配列として返してくれます。

```ruby
# 結果のイメージ
["A-1", "B-3", "C-2"]
```

`Seat` オブジェクトを一つ一つ生成するよりもはるかに軽量で高速なため、特定のデータだけが欲しい場合に非常に有効なテクニックです。

---

## まとめ

この一連のコードは、

1.  **お店の全座席**を起点に (`@store.seats`)
2.  それぞれの**予約記録を横に並べ** (`.joins(:reservations)`)
3.  **「予約済み」か「使用中」の記録**だけを探し (`.where(...)`)
4.  最後にその**座席番号だけを抜き出す** (`.pluck(:seat_number)`)

という、非常に効率的で読みやすい方法で「予約済みの座席番号リスト」を取得しています。

これは、SQLを直接書くのではなく、Rubyのコードで直感的にデータベースを操作できる Rails (Active Record) の強力な機能の一つです。
