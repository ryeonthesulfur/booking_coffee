# 解説：flatpickrのdateFormat - なぜ2つのフォーマットが必要か？

flatpickr（カレンダー）の設定を見ていると、`dateFormat`と`altFormat`という、よく似た2つの書式設定があります。

```javascript
// seats_index.js の一部
flatpickr(".reservation-date-input", {
  // ...
  altInput: true,
  altFormat: "Y年m月d日 H時i分", // ← ユーザーに見せる書式
  dateFormat: "Y-m-d H:i",      // ← サーバーに送る書式
  // ...
});
```

なぜ、わざわざ2つの書式を使い分ける必要があるのでしょうか？
それは、**「人間にとっての分かりやすさ」**と**「機械（サーバー）にとっての扱いやすさ」**を両立させるためです。

---

## 2つのフォーマットの役割

### `altFormat: "Y年m月d日 H時i分"`

-   **役割:** ユーザーの目に直接触れる、画面上の入力欄に表示される書式です。
-   **目的:** 日本語の「年」「月」「日」などを使うことで、誰にとっても直感的で分かりやすい表示にします。人間向けの**「表示用フォーマット」**です。

### `dateFormat: "Y-m-d H:i"`

-   **役割:** 実際にサーバー（Rails）に送信される、裏側のデータ形式です。
-   **目的:** `2026-06-10 15:30` のように、世界中のどのプログラムでも解釈しやすい、標準的でシンプルな形式にします。機械向けの**「送信用フォーマット」**です。

---

## `altInput: true` の魔法

この2つのフォーマットを機能させるために不可欠なのが `altInput: true` という設定です。

これを`true`にすると、flatpickrは以下のような賢い動きをします。

1.  画面上には、`altFormat`で整形された、人間にとって分かりやすい入力欄を**新たに見せます**。
2.  本来のHTMLの`<input>`タグは**画面上から隠します**。
3.  そして、その隠された`<input>`タグの中に、`dateFormat`で整形された、機械にとって扱いやすい値をこっそりと保持します。

フォームが送信されるとき、実際にサーバーに送られるのは、この**隠された`<input>`タグの値**です。

---

## 結論

この仕組みのおかげで、ユーザーは「2026年06月10日 15時30分」という親切な表示を見ながら操作でき、一方でサーバー側は `2026-06-10 15:30` という処理しやすいデータを安定して受け取ることができます。

`altInput`は、優れたUI/UX（ユーザー体験）と、堅牢なバックエンド処理を両立させるための、非常に重要な設定なのです。
