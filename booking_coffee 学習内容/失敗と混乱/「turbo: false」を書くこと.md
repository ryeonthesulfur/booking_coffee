# 解説：なぜフォーム送信が成功しても画面遷移しないのか？ (Turboの挙動)

ご提示のログと会話は、Rails 7から標準となった「Turbo」の挙動に起因する問題です。サーバーの処理は成功しているのに、ブラウザの画面が変わらないという状況を解き明かします。

---

## 状況の整理

1.  **やりたいこと**: 入力フォームから「確認画面へ進む」ボタンを押し、別の「確認ページ」に移動したい。
2.  **起きたこと**: ボタンを押しても画面が変わらない。しかし、サーバーのログを見ると `Completed 200 OK` となっており、処理は成功している。

---

## 犯人は誰？

ログの中のこの一行が、すべての謎を解く鍵です。

```
Processing by ReservationsController#confirm as TURBO_STREAM
```

`as TURBO_STREAM` とは、**「このリクエストはTurboによって乗っ取られ、処理されています」** という意味です。

---

## Turboのデフォルトの仕事：ページ遷移をさせないこと

Turboの主な目的は、Webサイトをまるでスマホアプリのようにサクサク動かすことです。そのために、**原則としてページ全体の再読み込み（画面遷移）をしません。**

`form_with` で作られたフォームは、デフォルトでTurboが有効になっています。

### Turboが有効な場合のフォーム送信の流れ

1.  ユーザーが送信ボタンを押す。
2.  Turboがその送信を**横取り（インターセプト）**します。
3.  ブラウザは画面遷移せず、Turboが裏側でサーバーにデータを送信します（これをAJAX通信と呼びます）。
4.  サーバーは処理を行い、レスポンスを返します。
5.  Turboは、そのレスポンスを使って**現在のページの一部だけを書き換える**ことを期待します。

### 今回、何が問題だったのか？

-   あなたのサーバーは、レスポンスとして「確認画面のページ全体のHTML」を返しました。
-   しかし、Turboが期待していたのは「現在のページの一部をどう書き換えるか」という指示書（Turbo Stream）でした。
-   期待と違うもの（ページ全体のHTML）が送られてきたため、Turboは「どうすればいいか分からない…」となり、**結果として何もせず、画面がそのまま**になってしまったのです。

---

## 解決策：`data: { turbo: false }` という「お断り状」

`data: { turbo: false }` は、特定のフォームに対して **「Turboさん、このフォームは横取りしなくて結構です」** と伝えるための「お断り状」です。

```erb
<%= form_with model: @reservation, ..., data: { turbo: false } do |f| %>
```

これを付けると、そのフォームはTurboに無視され、昔ながらのWebの仕組みで送信されます。

1.  ユーザーが送信ボタンを押す。
2.  ブラウザは、ページ全体を再読み込みして、指定されたURLにデータを送信する（通常の画面遷移）。
3.  サーバーが返した「確認画面のページ全体のHTML」を、ブラウザがそのまま新しいページとして表示する。

これにより、あなたが意図した通りの「確認画面へのページ遷移」が実現できるのです。

## まとめ

-   **Turboのままが良い場合**: フォーム送信後、ページ遷移せずに一部だけ（コメント欄など）を更新したいとき。
-   **`turbo: false` が必要な場合**: フォーム送信後、完全に別のページに移動したいとき（今回の確認画面など）。
