# 15分自動キャンセル機能 実装レポート
日付：2026-06-10

---

## 概要

予約日時から15分経過してもチェックインしなかった場合、予約を自動キャンセルする機能の実装。
あわせて、ステータス表示・チェックインボタン・退店ボタンをビューに追加する。

---

## 仕様まとめ

### ステータスの流れ

```
reserved(0) ──チェックインボタンを押す──▶ using(1) ──退店する──▶ データ削除
     │
     └──15分経過・未チェックイン──▶ メール通知 ＋ データ削除（Job が自動実行）
```

### 予約詳細画面のボタン切り替え

| タイミング | 表示ボタン |
|---|---|
| 予約日時**前** | 「予約をキャンセルする」のみ（データ削除） |
| 予約日時**になったら** | 「チェックイン」が左隣に追加される |
| チェックイン後（using） | 両方消えて「退店する」が出る（データ削除） |

### 予約一覧画面

- 「間取り図」ボタンの左隣にステータスバッジを追加（予約済 / 利用中）

### 自動キャンセルJobの仕組み

- `reserved` かつ `start_time` が15分以上前の予約を毎分チェック
- 該当する予約が見つかったらキャンセル通知メールを送信 → データ削除

### 使用技術

- バックグラウンドジョブ：Rails 8 組み込みの **SolidQueue**（追加gemなし）
- スケジュール設定：`config/recurring.yml`
- メール送信：SendGrid（既存設定を流用）

## 実装手順

### ① ルーティング（完了）

**ファイル：** `config/routes.rb`

```ruby
# 変更前
resources :reservations, only: [ :index, :show, :destroy ]

# 変更後
resources :reservations, only: [ :index, :show, :destroy ] do
  member do
    patch :check_in
  end
end
```

**解説：**

`member do ... end` は「特定の1件のリソースに対する操作」のルートを追加するブロック。
`patch` はデータの**更新**に使うHTTPメソッド（ステータスを `reserved → using` に変えるため）。

これにより以下のルートが生成される：
```
PATCH /reservations/:id/check_in → reservations#check_in
```

ビューでは `check_in_reservation_path(@reservation)` というヘルパーで呼び出せる。

確認コマンド：
```bash
bin/rails routes | grep check_in
# → check_in_reservation PATCH /reservations/:id/check_in reservations#check_in
```

### ② コントローラー（完了）

**ファイル：** `app/controllers/reservations_controller.rb`

```ruby
def check_in
  @reservation = current_user.reservations.find(params[:id])
  @reservation.update!(status: :using)
  redirect_to reservation_path(@reservation), notice: "チェックインしました。"
end
```

**解説：**

- `current_user.reservations.find(...)` ：自分の予約しか操作できないセキュアな書き方。他人の予約IDを直打ちされても弾ける。
- `update!(status: :using)` ：ステータスを `using（利用中）` に更新。

**`update` と `update!` の違い：**

```ruby
# update（!なし）→ 失敗しても処理が続く。失敗に気づけない可能性がある。
@reservation.update(status: :using)

# update!（!あり）→ 失敗したら即エラーになって処理が止まる。
@reservation.update!(status: :using)
```

ATMで例えると：
- `update` → エラーが起きても「完了しました」と表示されてしまう
- `update!` → エラーが起きたら「エラーが発生しました」と表示して止まる

チェックインのような「確実に成功してほしい操作」には `!` をつけるのが一般的。

- `redirect_to reservation_path(@reservation)` ：チェックイン後、同じ詳細画面に戻る。

### ③ メーラーの作成（完了）

**ファイル：** `app/mailers/reservation_mailer.rb`

雛形の生成コマンド：
```bash

```

生成されるファイル：
```

test/mailers/reservation_mailer_test.rb  ← テストファイル（今回は使わない）
```

```ruby
class ReservationMailer < ApplicationMailer
  def reservation_cancelled(reservation)
    @reservation = reservation
    @user = reservation.user
    mail(to: @user.email, subject: "【booking coffee】ご予約が自動キャンセルされました")
  end
end
```

**メーラーとは：**

コントローラーとビューの関係に似ている。

| Web画面 | メール |
|---|---|
| コントローラー | メーラー |
| ビュー（.html.erb） | メールビュー（.html.erb） |

コントローラーが「どのビューを表示するか」を決めるように、メーラーが「誰に・何の件名で・どのビューを使うか」を決める。

**解説：**

- `def reservation_cancelled` がメールの種類を定義するメソッド
- `@reservation` と `@user` はメールビューで使えるインスタンス変数になる
- `mail(to:, subject:)` が「誰に」「件名は何」を指定する部分

### ⑤ 自動キャンセルJobの作成（完了）

**ファイル：** `app/jobs/cancel_no_show_reservations_job.rb`

雛形の生成コマンド：
```bash
bin/rails generate job CancelNoShowReservations
```

```ruby
class CancelNoShowReservationsJob < ApplicationJob
  queue_as :default

  def perform
    Reservation.reserved.where(start_time: ..15.minutes.ago).each do |reservation|
      ReservationMailer.reservation_cancelled(reservation).deliver_now
      reservation.destroy
    end
  end
end
```

**Jobとは：**

普通のRailsの処理は「リクエストが来たら即座に実行」だが、Jobは**バックグラウンドで定期的に実行できる処理**のこと。
SolidQueue（Rails 8 組み込み）が管理するため、追加のgemやRedisは不要。

**解説：**

- `Reservation.reserved` ：ステータスが `reserved` の予約だけを対象にする
- `.where(start_time: ..15.minutes.ago)` ：予約日時が15分以上前のものだけ絞り込む（`..` は「以下」の範囲指定）
- `deliver_now` ：メールをその場で即送信する
- `reservation.destroy` ：メール送信後にデータ削除

**`*args` について：**

generateコマンドで生成されると `def perform(*args)` と書かれているが、今回は外からデータを渡す必要がないので削除する。
`*` は「いくつでも引数を受け取れる」という意味で、今回のJobは自分でDBを検索するため不要。

### ⑥ スケジュール設定（完了）

**ファイル：** `config/recurring.yml`

```yaml
production:
  clear_solid_queue_finished_jobs:
    command: "SolidQueue::Job.clear_finished_in_batches(sleep_between_batches: 0.3)"
    schedule: every hour at minute 12

  cancel_no_show_reservations:
    class: CancelNoShowReservationsJob
    schedule: every minute
```

**`recurring.yml` とは：**

SolidQueue（Rails 8 組み込みのジョブ管理システム）に対して、「このJobをいつ・どのくらいの頻度で実行するか」を指定するファイル。
Railsサーバーが起動しているあいだ、ここに書いたスケジュールに従って自動でJobが実行される。

Sidekiqや外部cronサービスは不要。Gemの追加も不要。Rails 8 なら最初から使える。

**今回追記した内容の解説：**

```yaml
cancel_no_show_reservations:    # スケジュールの名前（任意）
  class: CancelNoShowReservationsJob  # 実行するJobクラス名
  schedule: every minute              # 毎分実行する
```

- `cancel_no_show_reservations` ：このスケジュールの識別名。何でもOKだが、わかりやすい名前にする。
- `class: CancelNoShowReservationsJob` ：毎分呼び出すJobクラスを指定。
- `schedule: every minute` ：1分ごとに実行するという意味。

**すでに書いてあった1行の解説：**

```yaml
clear_solid_queue_finished_jobs:
  command: "SolidQueue::Job.clear_finished_in_batches(...)"
  schedule: every hour at minute 12
```

これはRailsが最初から用意していたもので、「Jobの実行履歴データを毎時12分に掃除する」という設定。
`class` の代わりに `command` を使うと、Jobクラスを作らずに直接Rubyコードを実行できる。

### ⑦ 予約一覧ビュー（完了）

**ファイル：** `app/views/reservations/index.html.erb`

既存の「間取り図」ボタンをラップする形でステータスバッジを追加。

```erb
<div class="reservation-card__actions">
  <span class="status-badge status-badge--<%= r.status %>">
    <% if r.reserved? %>
    予約済
    <% elsif r.using? %>
    利用中
    <% end %>
  </span>
  <%= link_to "間取り図", reservation_path(r), class: "reservation-card__link" %>
</div>
```

**enumが自動で作るメソッドについて：**

`reservation.rb` に以下を書いた瞬間、Railsが自動でメソッドを生成してくれる：

```ruby
enum :status, { reserved: 0, using: 1, checked_out: 2 }
```

自動生成されるメソッド一覧：

```ruby
# 判定メソッド（true/falseを返す）
r.reserved?       # reservedかどうか
r.using?          # usingかどうか
r.checked_out?    # checked_outかどうか

# 更新メソッド（そのステータスに変更する）
r.reserved!
r.using!

# スコープメソッド（該当ステータスの一覧を取得）
Reservation.reserved      # reservedの予約を全件取得
Reservation.using         # usingの予約を全件取得
```

Jobの中で使った `Reservation.reserved.where(...)` もこのenumが作ったスコープメソッド。

**`status-badge--<%= r.status %>` の意味：**

`r.status` は `"reserved"` や `"using"` という文字列を返すので、動的にCSSクラスが変わる。

```
予約済の場合 → class="status-badge status-badge--reserved"
利用中の場合 → class="status-badge status-badge--using"
```

これでCSSで色分けできる（後で整える）。

### ⑧ 予約詳細ビュー（完了）

**ファイル：** `app/views/reservations/show.html.erb` ＋ `app/views/reservations/_reservation_actions.html.erb`

ボタンの条件分岐は**部分テンプレート（パーシャル）** に切り出した。

**パーシャルとは：**

ビューの一部を別ファイルに切り出す仕組み。ファイル名の先頭に `_`（アンダースコア）をつける。
`show.html.erb` がすっきりして読みやすくなる。

`show.html.erb` 側の呼び出し：
```erb
<%= render "reservation_actions", reservation: @reservation %>
```

- `"reservation_actions"` → `_reservation_actions.html.erb` を呼ぶ
- `reservation: @reservation` → パーシャル内で使う変数名と値を渡す
- パーシャル内では `@reservation`（`@`あり）ではなく `reservation`（`@`なし）で使う

**`_reservation_actions.html.erb` の中身：**

```erb
<div class="reservation-actions">
  <% if reservation.using? %>
    <%= button_to "退店する", reservation_path(reservation), method: :delete,
          data: { turbo_confirm: "退店しますか？" },
          class: "checkout-btn" %>

  <% elsif Time.current >= reservation.start_time - 15.minutes %>
    <%= button_to "チェックイン", check_in_reservation_path(reservation), method: :patch,
          data: { turbo_confirm: "チェックインしますか？" },
          class: "checkin-btn" %>
    <%= button_to "この予約をキャンセルする", reservation_path(reservation), method: :delete,
          data: { turbo_confirm: "本当にキャンセルしますか？" },
          class: "cancel-btn" %>

  <% else %>
    <%= button_to "この予約をキャンセルする", reservation_path(reservation), method: :delete,
          data: { turbo_confirm: "本当にキャンセルしますか？" },
          class: "cancel-btn" %>
  <% end %>
</div>
```

**条件分岐の読み方：**

```
① reservation.using? が true
　→ チェックイン済み → 「退店する」ボタンのみ表示

② Time.current >= reservation.start_time - 15.minutes
　→ 予約時刻の15分前以降 → 「チェックイン」＋「キャンセル」を表示

③ それ以外（予約時刻の15分以上前）
　→「キャンセル」ボタンのみ表示
```

`reservation.start_time - 15.minutes` は「予約時刻の15分前」という意味。
Railsの時間計算は `- 15.minutes` のように自然な英語に近い書き方ができる。
