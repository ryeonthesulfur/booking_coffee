

================================================================
  STEP 1：GitHubからアプリをEC2にクローン
================================================================

EC2のターミナルで実行する。

【1-1】Gitのバージョン確認
  git --version
  → バージョンが表示されればOK

【1-2】アプリをクローンする
  cd ~
  git clone https://github.com/ryeonthesulfur/booking_coffee.git
(cd ~ && git clone https://github.com/ryeonthesulfur/booking_coffee.git)

  完了後、確認：
  ls
  → booking_coffee フォルダが表示されればOK

【1-3】アプリのフォルダに移動
  cd booking_coffee


================================================================
  STEP 2：必要なgemをインストール
================================================================

【2-1】本番環境用でbundle installを実行
  bundle config set without 'development test' && bundle install

  ⚠️ 古いコマンド「bundle install --without development test」は
     Bundler 2.x以降では使えないので注意。


  完了まで数分かかる。





■ ここまでで何をやってきたか？（STEP1〜2の全体像）
----------------------------------------------------------------
ここまでの作業は大きく2つのことをやっていた。

【GitHubクローン（STEP 1）】
  GitHubに上げてあるアプリのコードを、EC2サーバーの中にコピーしてきた。
  自分のMacで開発していたアプリが、そのままEC2の中に入ってきたイメージ。
  ただしこの時点では「コードがある」だけで、まだアプリは動かせない。


【bundle install（STEP 2）】
  アプリを動かすために必要なgem（部品・ライブラリ）を、EC2にまとめてインストールした。
  自分のMacでも最初に「bundle install」をやったのと同じことを、EC2でもやった。

  ※gemの中にはC言語でコンパイルが必要なものがあり、
    EC2にコンパイラや開発用ヘッダーファイルが揃っていなかったため
    エラーが連続して発生した。（詳細は bundle_installエラー解説.txt を参照）


【合わせてこういう状態になった】
  EC2の中に：
    ・アプリのコード  → git cloneで持ってきた
    ・動かすための部品 → bundle installで揃えた

  次は「データベースの準備」と「起動設定」をすれば、
  ようやくアプリが動き出せる状態になる。








STEP 1〜2で直面したエラー一覧

Killed（強制終了）
t3.microのRAMは1GBしかなく、gemのコンパイル中にメモリ不足でOSに強制終了された
→ スワップファイル1GBを作成して対処

PermissionError（書き込み権限エラー）
aptでインストールしたRubyはgemを /var/lib/gems/ に保存しようとするが、そこはroot専用で書けない
→ bundle config set path vendor/bundle でプロジェクト内に保存先を変更

development tools first（コンパイラエラー）
ruby-full はRuby本体だけで、C言語でRubyを扱うためのヘッダーファイルが含まれていない
→ sudo apt install -y ruby3.3-dev で追加インストール

Disk quota exceeded（/tmp容量不足）
/tmp はメモリ上の領域で455MBしかなく、失敗ビルドのゴミが残って満杯になっていた
→ export TMPDIR=~/tmp でコンパイル一時ファイルの置き場をディスク上に変更

mysql client is missing（MySQLライブラリ不足）
mysql2 gemはC言語レベルでMySQLと通信するため開発用ライブラリが必要だが、mysql-client（CLIツール）しか入っていなかった
→ sudo apt install -y libmysqlclient-dev で解決



gcc --version について

gcc は GNU C Compiler、つまりC言語のコンパイラです。

gemの中にはC言語で書かれた部分を持つものがあります（mysql2やnokogiriなど）。
それをインストールするとき、EC2上でC言語のコードを「コンパイル（機械語に変換）」する必要があります。

gcc --version は「このEC2にコンパイラが入っているか？バージョンは？」を確認するコマンドです。
build-essential をインストールするとgccも一緒に入ります。











sudo

「スードゥ」と読みます。Super User DO の略です。

Linuxには「管理者（root）」という最高権限のユーザーがいて、システムファイルの変更やソフトのインストールは管理者しかできません。

sudo をコマンドの前に付けると「今だけ管理者権限を借りてこのコマンドを実行する」という意味になります。


sudo apt install nginx
→ 管理者権限でnginxをインストールする
Windowsで言う「管理者として実行」と同じイメージです。




apt

Ubuntu（Linuxの一種）に標準搭載されているソフトウェアの管理ツールです。Advanced Package Tool の略。

「パッケージ」＝ソフトウェアのまとまりのことで、aptを使うとインターネットから公式のソフトをダウンロード・インストール・削除できます。


sudo apt install nginx   → nginxをインストール
sudo apt update          → インストールできるソフト一覧を最新にする
sudo apt upgrade         → インストール済みのソフトを最新版にする
MacでいうHomebrew（brew install）と同じ役割です。






今のところの理解まとめると、アプリをデプロイするために、AWSというデータベースサーバーを用いた。

そこにはアプリサーバーのEC2 とデータベースのRDSの二つがあって、
前半の作業ではこの二つの作成と設定、そして二つの接続を許可するために、
なんか忘れたけど、エンドポイントとか、 VPCとかアドレスとかポートがどうだとか、色々なんか二つを紐づける設定をインバウンドルールでやったんだよね。
何がどう紐づいてるのか忘れたから確認したいけど。

それから後半は、まず、EC2にRails のアプリを起動するための環境構築をするために色々インストールしたんだよね？
クローンがなんだったのか意味がよくわからないけど。
インストールするために事前に整えておかなきゃいけない要素が欠けてたり、
そもそもEC2の無料枠のメモリ不足で、スワップ領域という空きメモリを確保せざるを得なくなったんだったね。

あとはなんだっけ、なんか権限者エラーとか合ったよね。それでなんかの保存先をどっかに変えたんだったよね。

で、その後、データベースサーバーを本番環境で使うための紐付けと、環境変数によるセキュリティ設定をしたんだっけ。





前半：EC2とRDSの紐づけについて

EC2とRDSを繋ぐために必要だったのは：

・VPC → EC2とRDSが同じ「プライベートネットワーク」の中にいること
・インバウンドルール → RDSのセキュリティグループに「EC2のプライベートIPからのポート3306の通信を許可する」ルールを追加した
・エンドポイント → EC2からRDSに接続するときの「RDSのアドレス」

ハマったのは「パブリックIPでインバウンドルールを設定していたが、同じVPC内の通信はプライベートIPを使う」という落とし穴でした。



後半：環境構築について

クローンは「GitHubにあるアプリのコードをEC2にコピーしてきた」だけです。この時点ではまだ動かせない。

bundle installで「動かすための部品（gem）を全部EC2にインストールした」ところで初めて動かせる状態の一歩手前になりました。

権限エラーの解決は「gemの保存先を /var/lib/gems/（root専用）から vendor/bundle（プロジェクト内）に変更した」です。

後半：データベースの紐づけ

/etc/environment → パスワードをEC2内に安全に保存
database.yml → RDSのアドレス・ユーザー名・パスワードの読み込み先を設定
この2つで「RailsがRDSに繋がれる」状態になりました。







そもそも VPC、インバウンドルール、エンドポイントがなんなのかよくわからない



それぞれ説明します。

・どのユーザーで繋ぐか（マスターユーザー名）VPC（Virtual Private Cloud）

AWSの中に作る「プライベートなネットワーク空間」です。
EC2とRDSはAWSの広大なクラウドの中にありますが、VPCという「仕切り」の中に一緒に入れることで、同じネットワーク内として扱えます。

イメージ：同じマンションの中にEC2とRDSが住んでいる。マンションの外からは直接RDSに触れない。


・インバウンドルール

「外から中への通信を許可するルール」です。
デフォルトでは全ての接続が拒否されています。なのでRDSに対して「EC2からのMySQL通信（ポート3306）だけ許可する」というルールを明示的に追加する必要がありました。

イメージ：マンションのオートロック。「この人だけ入れる」と登録する作業。


・エンドポイント

RDSサーバーのアドレス（URL）です。
自分のMacで開発中はMySQLのアドレスが localhost でしたが、本番ではRDSのアドレスを指定する必要があります。
それがエンドポイントで、database.yml の host: に書いたものです。

イメージ：マンションの住所。ここに手紙（通信）を送る。



3つの関係をまとめると：

VPC → EC2とRDSを同じネットワークに入れる
インバウンドルール → EC2からRDSへの通信を許可する
エンドポイント → EC2がRDSのどこに接続するかのアドレス
この3つが揃って初めてEC2からRDSに繋がります。
