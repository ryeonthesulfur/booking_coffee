# 解説：予約修正フローのバグとクエリパラメータによる解決    260624

---

## 1. 発端：予約修正で入力内容がリセットされるバグ

予約機能において、ユーザーが入力内容を確認する画面(`confirm.html.erb`)から「予約内容を修正する」ボタンを押して予約フォーム(`new.html.erb`)に戻った際に、
せっかく入力した日時や人数がリセットされ、現在時刻から次の30分スロットが初期値になってしまう、という問題が発生しました。

これは、確認画面からフォーム画面へ情報を引き継げていないことが原因です。

## 2. 最初の試みと新たなエラー

この問題を解決するため、`confirm.html.erb` の「修正する」リンクに、`@reservation` オブジェクトが持つ情報を渡そうと試みました。

```erb
<%# エラーになるコード %>
<%= link_to "予約内容を修正する", new_store_seat_reservation_path(
  @store,
  @seat.seat_number,
  start_time: @reservation.start_time.strftime("%Y/%m/%d %H:%M〜"),
  @reservation.num_people,
  @reservation.phone_number,
  @reservation.notes
), class: "btn-edit", data: { turbo: false } %>
```

しかし、このコードは `ActionView::SyntaxErrorInTemplate` という文法エラーを引き起こしました。

**エラーの原因**: Rubyのメソッド呼び出しのルールでは、**キーワード引数（`key: value` の形式）の後ろに、位置引数（値だけの形式）を置くことはできません。** 上記コードでは、`start_time:` というキーワード引数の後に `@reservation.num_people` という位置引数が続いているため、文法エラーとなっていました。

## 3. 解決策：`path_helper` とクエリパラメータの正しい使い方

このエラーを解決し、正しく情報を引き継ぐには、Railsの `path_helper`（`xxx_path` という名前のメソッド群）が引数をどのように解釈するかを理解する必要がありました。

### 位置引数 vs キーワード引数

-   **位置引数**: ルーティングで定義された動的な穴（例：`/stores/:store_id/seats/:seat_id` の `:store_id` と `:seat_id`）を**順番に**埋めるために使われます。
-   **キーワード引数**: ルートの穴を埋め終わった後に残った「名前付き」の引数は、URLの末尾に **クエリパラメータ** (`?key=value&...`) として自動的に追加されます。

`new_store_seat_reservation_path` が必要とする位置引数は `:store_id` と `:seat_id` の2つだけです。それ以上の情報を渡したい場合は、すべてキーワード引数にする必要があります。

### 正しいコード

```erb
<%# 正しいコード %>
<%= link_to "予約内容を修正する", new_store_seat_reservation_path(
  @store,                                     # 1. 位置引数 (routesの :store_id に入る)
  @seat.seat_number,                          # 2. 位置引数 (routesの :seat_id に入る)
  start_time: @reservation.start_time.strftime("%Y/%m/%d %H:%M"), # 3. キーワード引数 (クエリパラメータになる)
  num_people: @reservation.num_people,        # 4. キーワード引数 (クエリパラメータになる)
  phone_number: @reservation.phone_number,    # 5. キーワード引数 (クエリパラメータになる)
  notes: @reservation.notes                   # 6. キーワード引数 (クエリパラメータになる)
), class: "btn-edit", data: { turbo: false } %>
```

このコードによって、以下のようなURLが生成されます。

```
/stores/1/seats/A-1/reservations/new?start_time=...&num_people=2&phone_number=...&notes=...
└────────── パス部分 ────────────────┘└─────────────── クエリパラメータ部分 ───────────────┘
```

「URLを使って次の画面にデータを渡す」という仕組みの実体が、このクエリパラメータです。


## 4. データの受け取り：コントローラー側の対応

URLに情報を乗せて渡すだけでは不十分です。受け取り側である `ReservationsController` の `new` アクションが、その値を読み取ってフォームの初期値として設定する必要があります。

### なぜ `reservation_params` は使えないのか？

`create` アクションで使っている `reservation_params` を流用しようと考えがちですが、これはエラーになります。

```ruby
# createアクションで使われるStrong Parameters
def reservation_params
  params.require(:reservation).permit(...)
end
```

`params.require(:reservation)` は、`params` の中に `reservation` というキーが存在し、その中に各パラメータがネストされていること（例：`params[:reservation][:start_time]`）を前提としています。

しかし、今回クエリパラメータで渡されるデータはネストされておらず、フラットな構造（`params[:start_time]`）です。そのため、`params[:reservation]` が見つからず `ActionController::ParameterMissing` エラーが発生します。

### 正しい `new` アクションの実装

フラットなパラメータを受け取るには、`.require` を使わずに `.permit` を直接呼び出します。

```ruby
# app/controllers/reservations_controller.rb

def new
  @seat = Seat.find_by(seat_number: params[:seat_id], store_id: params[:store_id])
  @store = Store.find(params[:store_id])

  # クエリパラメータで渡された値を Reservation.new の初期値として設定する
  # params.permit(...) は、許可されたキーを持つハッシュを返す
  @reservation = Reservation.new(params.permit(:start_time, :num_people, :phone_number, :notes))
end
```

この実装により、`params` から `start_time`, `num_people`, `phone_number`, `notes` の値だけを安全に取り出し、`@reservation` オブジェクトの初期値として設定できます。これにより、フォーム画面には修正前の値が正しく表示されるようになります。

## 5. まとめ

-   **`link_to` で追加情報を渡す**: ルートの穴を埋める位置引数以外のデータは、キーワード引数として渡すことでクエリパラメータになる。
-   **クエリパラメータの受け取り**: コントローラーでは、ネストされていない `params` として直接アクセスできる。
-   **Strong Parametersの使い分け**:
    -   ネストされたフォームデータには `params.require(:model).permit(...)`
    -   フラットなクエリパラメータには `params.permit(...)`
-   **エラーからの学び**: `SyntaxError` は、Rubyの基本的な文法ルール違反を示唆している。`path_helper` のようなRailsの便利機能も、Rubyの文法の上で成り立っていることを理解することが重要。
