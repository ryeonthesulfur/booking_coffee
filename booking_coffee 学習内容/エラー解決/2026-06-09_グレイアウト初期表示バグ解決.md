# バグ解決：初期表示でグレイアウトが反映されない

## 発生日
2026-06-09

## 症状①：ページ初期表示（日時未選択）でグレイアウトにならない

### 原因
`params[:start_time]` がない場合（初期表示）、elseブランチで `@reserved_seat_numbers = []` を返していた。
そのため、何も予約済みとして扱われず、全座席が予約可能に見えていた。

### 修正前
```ruby
else
  @reserved_seat_numbers = []
end
```

### 修正後
日時未選択のときは「次の30分スロット」を基準にしてグレイアウトを計算する。
```ruby
else
  now = Time.zone.now
  default_time = now.min < 30 ? now.change(min: 30, sec: 0) : now.change(hour: now.hour + 1, min: 0, sec: 0)
  @reserved_seat_numbers = @store.seats
    .joins(:reservations)
    .where(reservations: { status: [:reserved, :using] })
    .where("reservations.start_time > ? AND reservations.start_time <= ?", default_time - 3.hours, default_time)
    .pluck(:seat_number)
end
```

---

## 症状②：予約してもグレイアウトにならない（タイムゾーンバグ）

### 原因
`config/application.rb` の `config.time_zone = "Tokyo"` がコメントアウトされていた。

RailsのデフォルトタイムゾーンはUTC。そのためDBに保存される `start_time` が **UTC（日本時間-9時間）** で保存されていた。

例：日本時間17:30に予約 → DBにはUTC 08:30で保存される

一方、グレイアウトのwhere句では `Time.zone.now`（日本時間）を基準に比較するため、DB内のUTC時刻と一致せず、グレイアウトにならなかった。

### 修正
```ruby
# config/application.rb
config.time_zone = "Tokyo"
```

これにより `Time.zone.now` も `start_time` の保存もすべて日本時間（JST）で統一される。

---

## 修正ファイル
- `app/controllers/stores_controller.rb`（elseブランチ）
- `config/application.rb`（タイムゾーン設定）
