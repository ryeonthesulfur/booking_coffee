================================================================
  toReservation_form.js 読み込み404エラー解説
  ── importのパス指定ミスによるJSファイル未読み込み ──
================================================================


================================================================
  発生したエラー
================================================================

ブラウザのコンソールに以下のエラーが表示された。

  Failed to load resource: the server responded with a status of 404 (Not Found)
  GET http://localhost:3000/assets/toReservation_form net::ERR_ABORTED 404 (Not Found)

座席を選択してボタンを押しても、seats#showに遷移しなかった。


================================================================
  原因
================================================================

application.js で以下のように書いていた。

  import "./toReservation_form"

Rails の importmap では、`./`（相対パス）でのimportは正しく解決されない。

importmap.rb で以下のようにピン留めしていた場合：

  pin "toReservation_form", to: "toReservation_form.js"

モジュール名は "toReservation_form"（`./` なし）として登録される。
`./toReservation_form` という相対パスはimportmapで解決できず404になる。


================================================================
  解決策
================================================================

application.js の import の書き方を修正した。

【修正前】
  import "./toReservation_form"

【修正後】
  import "toReservation_form"

`./` を取り除くことで、importmapに登録されたモジュール名と一致し、
正しくファイルが読み込まれるようになった。


================================================================
  ポイント
================================================================

■ importmap での import の書き方

  - `pin "名前", to: "ファイル名.js"` で登録した場合
    → `import "名前"` で読み込む（`./` 不要）

  - `./` をつけると相対パスとして解釈され、
    importmapを経由しない読み込みになってしまう

■ 同じファイルがあっても404になる理由
  ファイル自体は存在していても、importmapが解決できないパスで
  importしていると、ブラウザはそのURLに直接アクセスしようとして
  404エラーになる。


================================================================
  なぜ `./` だとダメなのか？詳細なメカニズム
================================================================

`importmap` は、ブラウザに「モジュール名」と「実際のファイルパス」の対応関係を教える「辞書」のようなものです。

`config/importmap.rb` に `pin "toReservation_form", to: "toReservation_form.js"` と書くと、Railsは以下のような辞書をHTMLに埋め込みます。

```html
<script type="importmap">
{
  "imports": {
    "toReservation_form": "/assets/toReservation_form-a1b2c3d4e5f6.js"
  }
}
</script>
```
（`a1b2c3d4e5f6` の部分はアセットパイプラインが生成するハッシュ値）

この辞書を元に、ブラウザは `import` 文を解釈します。

---

### ❌ 間違った場合: `import "./toReservation_form"`

1.  **ブラウザの解釈**: `import` 文の中身が `./` で始まっています。これは「**相対パス**」を意味します。
2.  **ブラウザの動作**: ブラウザは「これは相対パスだから、**importmapの辞書は見ずに**、今いるファイル (`application.js`) からの相対的な位置にあるファイルを探そう」と判断します。
3.  **結果**: ブラウザは `http://localhost:3000/assets/toReservation_form` というURLに直接アクセスしようとします。しかし、Railsが実際に提供しているファイル名はハッシュ値付きの `toReservation_form-a1b2c3d4e5f6.js` です。そのため、ファイルが見つからず **404 Not Found エラー**になります。

---

### ✅ 正しい場合: `import "toReservation_form"`

1.  **ブラウザの解釈**: `import` 文の中身が `./` や `/` で始まっていません。これは「**裸のモジュール指定子 (bare module specifier)**」と呼ばれます。
2.  **ブラウザの動作**: ブラウザは「これは裸のモジュール名だから、**importmapの辞書で名前を探そう**」と判断します。
3.  **結果**: 辞書の中に `"toReservation_form"` というキーが見つかります。ブラウザは、その値である `/assets/toReservation_form-a1b2c3d4e5f6.js` という**正しいパス**にアクセスしにいきます。ファイルが正常に読み込まれ、JavaScriptが実行されます。

================================================================

座席を選択してボタンを押したところ、seats#showへの遷移を確認した。
