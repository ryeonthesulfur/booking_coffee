# 解説：URLSearchParamsによる画面間データ連携

`seats_index.js` で使われている以下のコードは、複数の画面にまたがるデータの引き継ぎを実現する上で、中心的な役割を担っています。

```javascript
const urlParams = new URLSearchParams(window.location.search);
const startTimeParam = urlParams.get('start_time');
```

---

## このコードがやっていること

一言で言うと、**「今いるページのURLの中から、『start_time』という名前で渡されてきた情報（この場合は日時）を取り出す」**という処理です。

これにより、前の画面でユーザーが選択した日時を、次の画面で復元したり、表示したりすることができます。

### コードの分解

1.  **`window.location.search`**
    ブラウザに表示されているURLの `?` 以降の部分（クエリ文字列）を丸ごと取得します。
    （例: `"?start_time=2026-05-17%2014%3A30%EF%BD%9E"`）

2.  **`new URLSearchParams(...)`**
    上記で取得した文字列を、クエリパラメータを簡単に扱うための便利な道具（オブジェクト）に変換します。

3.  **`.get('start_time')`**
    その道具を使い、「`'start_time'` というキーに紐づく値を取り出してください」と命令します。URLに `start_time` があればその値が、なければ `null` が返されます。

---

## アプリケーション内での2つの重要な役割

この仕組みは、アプリケーション内の2つの異なる場面で、それぞれ重要な役割を果たしています。

### 1. 間取り図画面での役割：選択した日時を「保持」し、予約状況を「更新」する

間取り図画面では、ユーザーがカレンダーで日時を選択すると、以下のサイクルが実行されます。

1.  **`onClose` イベント発火:** ユーザーがカレンダーを閉じると、`flatpickr` の `onClose` イベントが発火します。
2.  **URL書き換えとリロード:** JavaScriptが、選択された日時を `?start_time=...` として現在のURLに追加し、ページ全体をリロードします。
3.  **コントローラーの処理:** リロードされたリクエストを受け取った `stores_controller` は、URLに含まれる `params[:start_time]` を見て、その日時に予約済みの座席リスト (`@reserved_seat_numbers`) を再計算します。
4.  **JavaScriptでの値の復元:** リロード後の画面で `seats_index.js` が再度実行され、`urlParams.get('start_time')` がURLから日時を取得。カレンダーの表示を、ユーザーが選択した日時に復元します。

このサイクルにより、**URLが常に信頼できる唯一の情報源（Single Source of Truth）**となり、ユーザーの選択がUIに保持され、かつバックエンドの予約状況も正しく更新される、という堅牢な状態管理が実現されています。

### 2. 予約フォーム画面での役割：選択した日時を「引き継ぐ」

間取り図画面から予約フォーム画面へ遷移する際には、以下の流れでデータが引き継がれます。

1.  **ボタンクリック:** ユーザーが「予約を進める」ボタンをクリックします。
2.  **URL生成:** `toReservation_form.js` が、選択された座席IDと日時を元に、**次の画面（予約フォーム）のURL**を動的に組み立てます。このとき、日時は `?start_time=...` としてURLの末尾に追加されます。
3.  **画面遷移:** `window.location.href` によって、組み立てられたURLへ画面が遷移します。
4.  **JavaScriptでの値の復元:** 予約フォーム画面で `seats_index.js` が実行され、`urlParams.get('start_time')` がURLから日時を取得。カレンダーの初期値を、前の画面で選択した日時に設定します。

これにより、ユーザーは再度日時を選択する手間なく、スムーズに予約手続きを進めることができます。

---

## まとめ

`URLSearchParams` を活用することで、

-   画面をまたいだデータの受け渡しをシンプルに実現できる。
-   URLを情報源とすることで、フロントエンド（JS）とバックエンド（Rails）が同じ情報を共有し、整合性を保つことができる。

といったメリットがあり、アプリケーションの使いやすさと安定性を両立させています。
