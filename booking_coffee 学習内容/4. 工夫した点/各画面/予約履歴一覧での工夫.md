# 予約履歴一覧での工夫

---

ステータス表示（`r.reserved?`・`r.using?`）は確かに聞かれる可能性があります。

enumの説明と、Railsが自動で `reserved?` などのメソッドを生やしてくれる仕組みは話せると良いです。

もう1つ同じくらい聞かれやすいのが、コントローラー側の `includes(seat: :store)` です。

このビューでは `r.seat.store.name`・`r.seat.seat_type` のように予約→座席→店舗とアソシエーションを辿っていますが、  
`includes` が無いと予約の数だけDBへのクエリが走るN+1問題が起きます。

「N+1問題とはなんですか」「どう対処しますか」という質問は定番なので、この画面のコードを起点に説明できるようにしておくと良いと思います。

---

## ステータス表示のコード

```erb
<div class="reservation-card__actions">
  <span class="status-badge status-badge--<%= r.status %>" style="margin-right: 2rem;">
     <% if r.reserved? %>
      予約済
     <% elsif r.using? %>
      利用中
     <% end %>
  </span>
     <%= link_to "間取り図", reservation_path(r), class: "reservation-card__link" %>
</div>
```

---

## ステータス表示の分岐について ── enum の説明

予約履歴一覧画面では、予約状況に応じて、チェックイン前は「予約済」、チェックイン後は「利用中」というふうに表示を変えようとしました。  
そのため、予約状況を番号で管理するenumを用いました。

```ruby
enum :status, { reserved: 0, using: 1, checked_out: 2 }
```

---

## なぜ enum で管理したのか

- **パフォーマンス:** 文字列よりも整数の方が、検索や並び替え（インデックス）が高速だからです。
- **データサイズ:** 文字列よりも整数の方が、データベースの容量を節約できるからです。

ステータスカラム値は整数で管理されている。そこに予約状況を表す文字列を紐づけることで、  
Rails にとっても、人間にとっても直感的にわかりやすく、バグも減らせるからです。

---

## includes(seat: :store) の N+1問題

データベースの予約履歴のテーブルから座席と店舗のデータを持ってくるためにクエリを発行するのですが、  
`include` メソッドが無いと、予約履歴のデータ数の分、行ったり来たりしなくてはならなくなり、処理に負荷がかかるから。

---

## なぜ empty? を使いましたか

予約が0件のときに、そのまま何も表示しないのではなく『まだ予約がありません』というメッセージを出してユーザーに状況を伝えるためです。

技術的な補足としては、`@reservations` はActiveRecordのRelationなので、  
`nil` になる心配がなく `.empty?` が安全に使える、というのも答えに加えると良いです。
