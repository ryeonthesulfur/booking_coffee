# 予約フォームから完了画面までの画面遷移フロー

---

## 全体の流れ

```
予約フォーム（new）
    ↓ POST → reservations#confirm
確認画面（confirm）
    ↓ POST → reservations#create
完了画面（complete）
```

---

## ① 予約フォーム → 確認画面

「確認画面へ」ボタンを押す。

- `collection` + `POST` で `reservations#confirm` へ遷移
- 入力内容はリクエストボディに乗って送られる（URLにクエリパラメータとして露出しない）
- `confirm` アクションが入力内容を受け取り、確認画面を表示する

```
POST /stores/:store_id/seats/:seat_id/reservations/confirm
```

`collection` を使っている理由：まだDBに保存していないので `reservation.id` が存在しない。idが不要なアクションなので `collection`。

---

## ② 確認画面 → DB保存

「予約を確定する」ボタンを押す。

- 確認画面の `hidden_field` に埋め込まれていた予約内容が `POST` で `reservations#create` へ送られる
- `create` アクションがDBに保存する
- この時点で `@reservation.id` が確定する

```ruby
# hidden_field で運ばれてくる内容
:start_time, :num_people, :phone_number, :notes

# サーバー側で取得するもの（hidden_field 不要）
@user  → current_user
@store → params[:store_id] からDBで取得
@seat  → params[:seat_id] からDBで取得
```

---

## ③ DB保存 → 完了画面

`create` アクションの保存直後に `redirect_to` が走る。

```ruby
redirect_to complete_store_seat_reservation_path(@store, @seat, @reservation)
```

- `member` + `GET` で `reservations#complete` へ遷移
- 確定した `@reservation.id` を使って特定の1件にアクセスできる
- `@store`・`@seat` の情報を取得して完了画面に表示する

```
GET /stores/:store_id/seats/:seat_id/reservations/:id/complete
```

`member` を使っている理由：保存済みの特定の1件に対するアクションなので、idが必要。

---

## まとめ

| ステップ | HTTPメソッド | ルーティング | idの有無 |
|---|---|---|---|
| フォーム → 確認画面 | POST | `collection` | なし（保存前） |
| 確認画面 → 保存 | POST | `create`（標準） | なし（保存中） |
| 保存 → 完了画面 | GET | `member` | あり（保存後） |

「POSTでデータを運ぶ → 保存してidが確定 → idを使って完了画面へ」という流れ。
