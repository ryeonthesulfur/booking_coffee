
# What
ルーティング編集
・チェックインボタン用のルート
・reservations に check_in アクションを追記
・ステータスを'reserved → using'に変えるため、HTTPメソッドを更新のpatchで記述。
・アクション内は特定の一件のリソースに対する操作のため、「member - do」を採用。

reservations コントローラーの編集
・check_in アクションの記述
・自分の予約のみ操作できるように記述（current_user.reservations.find...）
・「update!(status: :using)」でステータスを「using(利用中)」に更新できる。
    「!」付きなので、失敗したらエラー扱いで処理が止まるようにしてあります。
・チェックイン後、お知らせのポップアップ表示

キャンセル時のメール送信機能
・予約がキャンセルになった時にユーザーに自動通知するためのメソッド定義。
・宛先と件名の記述

15分リミットの機能
・予約済のデータの中から、予約日時より15分経過した予約を毎分置きに探し、見つけ次第、自動通知の後、自動で削除する。

毎分置きに「15分リミット機能」を作動

自動通知メールのビュー作成
・15分経過後、予約キャンセルを通知するメールの内容

自動通知メールの一部修正
・サービス名のタイトルを修正

店舗メルアドの設定
・SendGrid で設定した店舗メルアドをRails 側に記述

予約履歴一覧ビューの編集
・enum のステータスから判断して「予約済」、「利用中」の表示切り替えを追加

部分テンプレートの追加
・コメントアウトの追記
・予約一覧詳細画面下部にて、「予約キャンセル」「チェックイン」「退店する」などアクションボタンをパーシャルで状況に応じて切り替え表示
・予約日時15分前に「チェックイン」できるようにこれを表示する条件分岐。



# Why
この15分リミットを実装した理由
・予約後ユーザーが利用しなかった場合、空席が埋まり続けてしまい他のユーザーが利用できず、店舗側の収益に損失が生じるため。

ルーティングに「check_in」アクションと member 〜 do を追加した理由
・ ログインした状態のユーザーが予約確定後チェックインした際に、パスとPATCHから、reservations コントローラーの「check_in」アクションに渡すよう判断させるため。
・ログインした状態のユーザーが行った、URL に特定の予約データの id を必要とするチェックインであるため。

reservations コントローラーにて、check_in アクションを記述した理由
・ログインした状態のユーザーが、自分の予約でチェックインできるようにするため。
・チェックインしたら、予約状態を「予約済」→「利用中」へ変えるため。
・チェックインしたら、ユーザーに「チェックインしました」と知らせるため。

キャンセル時のメール送信機能
・予約済みのユーザーが予約日時から15分経過してチェックインしなかった場合、自動通知を送信した履歴が、キャンセルされたかどうかの確認材料にもなりうるため。

4, 5. 毎分置きに「15分リミット機能」を作動させる理由
・予約日時から15分経過したかどうかを、毎分漏れなく自動判定するため。

自動通知メールのビュー作成
・予約日時から15分以内にチェックインしなかったユーザーから予約日時やキャンセル時についてクレームが入った場合、確認材料にするため。

SendGrid で設定した店舗メルアドをRails 側に記述した理由
・自動キャンセルのメール通知をタイムアウトしたユーザーに送信するため。

予約履歴一覧ビューに「予約済」、「利用中」の表示切り替えを追加した理由
・予約した直後と、チェックイン後でユーザーに予約の状況を視認させるため。

、「予約キャンセル」「チェックイン」「退店する」などアクションボタンをパーシャルに分けた理由
・予約履歴一覧の詳細ビューにそのまま記述すると全体が長くなり、一覧のコードが見づらくなるため。
・コード内にて、「link_to」はデフォルトのHTTPメソッドがGETのため、指定変更できる「button_to」を使用。
・予約日時よりも早めにチェックインできるようにすることで、ユーザーに余裕を持たせるため。

4ファイルの関係と役割を説明します。

application_mailer.rb — 全メールの共通設定

```ruby
default from: "sunftreflexi2032@gmail.com"
layout "mailer"
```
このアプリで送るすべてのメールの「差出人アドレス」と「レイアウトテンプレート」を1箇所で定義しています。


----------------------------------------------------------------------------------------
reservation_mailer.rb — キャンセル通知メールの定義

```ruby
def reservation_cancelled(reservation)
  mail(to: @user.email, subject: "【booking coffee】ご予約が自動キャンセルされました")
end
```
ApplicationMailerを継承しているので、差出人は上記の共通設定が使われます。「誰に」「件名は何」だけを指定しており、本文は別途 views/reservation_mailer/reservation_cancelled.html.erb に書かれています。

----------------------------------------------------------------------------------------

cancel_no_show_reservations_job.rb — 自動キャンセルのロジック

```ruby
Reservation.reserved.where(start_time: ..15.minutes.ago).each do |reservation|
  ReservationMailer.reservation_cancelled(reservation).deliver_now
  reservation.destroy
end
```

Reservation.reserved → ステータスが reserved のものだけ（enumのスコープ）
start_time: ..15.minutes.ago → 開始時刻が15分以上前のもの
メール送信 → 予約削除

----------------------------------------------------------------------------------------

recurring.yml — Solid Queueによる定期実行の設定

```yaml
cancel_no_show_reservations:
  class: CancelNoShowReservationsJob
  schedule: every minute
```

Rails 8のデフォルトバックグラウンドジョブ基盤である Solid Queue の機能で、
CancelNoShowReservationsJob を毎分実行するよう設定されています。
ただし、EC2上でSolid Queueのプロセス（bin/jobs）が起動していないと実際には動きません。

4つの関係まとめ

recurring.yml（毎分起動を指示）
  → CancelNoShowReservationsJob（対象予約を検索・処理）
    → ReservationMailer（キャンセルメール送信）
      → ApplicationMailer（差出人等の共通設定）
