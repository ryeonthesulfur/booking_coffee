# 解説：フラットパラメータとネストされたパラメータの違い    260624

---

`params.permit(...)` と `params.require(...).permit(...)` は、どちらもフォームなどから送られてくるデータを安全に受け取るための仕組み（Strong Parameters）ですが、扱うデータの構造に違いがあります。

その違いを理解する鍵が「フラットなパラメーター」と「ネストされたパラメーター」です。

---

## 1. ネストされたパラメーター（普段のフォーム送信）

`form_with model: @reservation` を使ってフォームを送信すると、Railsは気を利かせて、データを `reservation` というキーでまとめてくれます。

**送信されるデータ（イメージ）:**
`reservation[start_time]=...` & `reservation[num_people]=...`

**`params` の中身（イメージ）:**
```ruby
{
  "reservation" => {
    "start_time" => "2026-06-10 15:30",
    "num_people" => "2",
    "phone_number" => "09012345678"
  },
  "commit" => "予約を確定する",
  ...
}
```

このように、`params` の中の `reservation` キーの中に、さらにデータが入っている構造を**「ネストされた（入れ子になった）パラメーター」**と呼びます。

このネストされたデータから安全に値を取り出すのが、いつもの `reservation_params` です。

```ruby
# paramsの中から :reservation を必須(require)で取り出し、その中から許可(permit)したキーの値だけを取得する
params.require(:reservation).permit(:start_time, :num_people, :phone_number, :notes)
```

## 2. フラットなパラメーター（今回のクエリパラメーター）

一方、「修正する」リンクから送られてくるURLはこうなっています。
`/reservations/new?start_time=...&num_people=2&...`

このURLを受け取ったときの `params` の中身は、非常にシンプルです。

**`params` の中身（イメージ）:**
```ruby
{
  "start_time" => "2026-06-10 15:30",
  "num_people" => "2",
  "phone_number" => "09012345678",
  ...
}
```

`reservation` のような親キーがなく、`params` の直下にデータが並んでいます。この構造を**「フラットな（平坦な）パラメーター」**と呼びます。

このフラットなパラメーターに対して `params.require(:reservation)` を使おうとすると、「`reservation` なんてキーは無いよ！」とエラーになってしまいます。そこで、`.require` を使わずに直接 `.permit` を呼び出します。

```ruby
# .require を使わず、paramsから直接許可(permit)する
params.permit(:start_time, :num_people, :phone_number, :notes)
```

これは、「`params` の直下にあるキーの中から、指定したものだけを許可して取り出す」という命令です。

## まとめ

| | ネストされたパラメーター | フラットなパラメーター |
| :--- | :--- | :--- |
| **いつ使われるか** | `form_with model:` でのフォーム送信時 | URLのクエリパラメーターなど |
| **`params` の形** | `params[:reservation][:start_time]` | `params[:start_time]` |
| **受け取り方** | `params.require(:reservation).permit(...)` | `params.permit(...)` |
