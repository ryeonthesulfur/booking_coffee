# 解説：Railsのwhere句と時間範囲の謎を解く

```ruby
.where("reservations.start_time > ? AND reservations.start_time < ?", start_time - 3.hours, start_time + 3.hours)
```

この一行は、「選んだ日時に利用中になる予約を探す」ための条件式です。

---

## 1. 依頼書の構造を分解する

このコードは、大きく3つのパーツに分かれています。

```ruby
.where( ① "条件式", ② 値1, ③ 値2 )
```

-   `.where()`: データベースに「この条件に合うデータだけを探してください」とお願いする命令です。
-   **① "条件式"**: 探すための具体的なルールが書かれています。
-   **②, ③ 値**: ルールの中の `?` に入る、具体的な値です。

### 「条件式」を日本語に翻訳する

> `"reservations.start_time > ? AND reservations.start_time < ?"`

> 「`reservations`テーブルの`start_time`が、**ある値(?)**よりも**後(>)**で、**かつ(AND)**、**別の値(?)**よりも**前(<)**である」

`?` は「後で値を入れますよ」という目印（プレースホルダー）です。

---

## 2. なぜ「前後3時間」で探すのか？

各予約は**3時間の利用を想定**しています。

あなたが **15:00** を選んだとき、その時間帯に「かぶる」予約は以下の2パターンです。

| 既存の予約の開始時刻 | 利用時間 | 15:00にかぶるか？ |
|---|---|---|
| 12:30（3時間前より後） | 12:30〜15:30 | ✅ かぶる |
| 14:00 | 14:00〜17:00 | ✅ かぶる |
| 16:00（3時間後より前） | 16:00〜19:00 | ✅ かぶる |
| 12:00（ちょうど3時間前） | 12:00〜15:00 | ❌ 15:00で終わるのでかぶらない |
| 18:00（3時間後以降） | 18:00〜21:00 | ❌ あなたの予約が終わってから始まる |

つまり、**「選んだ時刻の前3時間〜後3時間の間に開始する予約」が競合する**ということになります。

---

## 3. 具体例で依頼書を完成させる

**「15:00」**を選んだ時の状況で、依頼書がどう完成するか見てみましょう。

-   `start_time` = `15:00`
-   `start_time - 3.hours` = `12:00`
-   `start_time + 3.hours` = `18:00`

```
依頼書（完成版）:
"reservations.start_time > '12:00' AND reservations.start_time < '18:00'"
```

日本語に翻訳すると：

> **「予約の開始時刻が、12:00よりも後で、かつ、18:00よりも前である」**

これが「15:00に利用中になる可能性のある予約」の条件です。

---

## 4. なぜ `>` と `<`（厳密な不等号）なのか？

### 下限（ `> 12:00`）の理由

「ちょうど12:00（3時間前）に始まった予約」は、12:00〜15:00の利用です。

あなたが予約したいのは **15:00から**なので、この席は15:00の時点で空きます。  
かぶらないので対象外。そのため `>=` ではなく `>` （12:00より後）にしています。

### 上限（ `< 18:00`）の理由

「ちょうど18:00（3時間後）に始まった予約」は、18:00〜21:00の利用です。

あなたの予約は15:00〜18:00なので、18:00の時点で終わります。  
かぶらないので対象外。そのため `<=` ではなく `<` （18:00より前）にしています。

---

## まとめ

この一行は、**「ユーザーが選んだ時刻に、本当に利用中となっている予約だけを、1秒のズレもなく正確に見つけ出す」**ための、非常に精密な条件式です。

| 項目 | 値（15:00を選んだ場合） |
|---|---|
| 下限（含まない） | 12:00（= 15:00 - 3時間） |
| 上限（含まない） | 18:00（= 15:00 + 3時間） |
| 対象となる既存予約 | 開始時刻が 12:00〜18:00 の間にある予約 |
