# 解説：予約システムの「3時間引く」ロジック（図解でわかる版）

「3時間制の予約なのに、なぜ『3時間引く』の？」。この疑問、分かります。
これは非常に混乱しやすいポイントです。

専門用語や難しい理屈は一旦すべて忘れて、たった一つの具体的な場面を「絵」で見ていきましょう。

---

## 1. 今の状況

-   **すでに存在する予約:**
    -   席「A-1」は、**14:00から**Aさんに予約されています。

-   **あなたのやりたいこと:**
    -   同じ席「A-1」を、**15:00から**予約したいと考えています。

-   **システムの仕事:**
    -   「15:00の時点で、席A-1は空いているか？」を判断すること。

---

## 2. 時間を「絵」で見てみよう

まず、Aさんの予約がどの時間帯を「占領」しているかを見てみます。
3時間制なので、14:00に始まった予約は17:00まで続きますね。

```
14:00 (予約開始) + 3時間 = 17:00 (利用終了)
```

これは、**未来の占有時間**を決めるための、単純な**足し算**です。

### 視点②：空席を「探す」システムの視点（過去を振り返る）

ここが本題です。あなたはシステム開発者です。ユーザーが「15:00」という時刻を選びました。

-   **「ユーザーが選んだ15:00の時点で、すでに誰かが使っている席はどれ？」**

システムは、データベースに記録されている**過去の予約**をすべてチェックして、`15:00` の時点で利用中の席を見つけ出さなければなりません。

この「過去を振り返ってチェックする」という作業こそが、「3時間引く」という計算が必要になる理由です。

---

## 本題：なぜシステムは「3時間引く」のか？

ユーザーが**「15:00」**という時刻を選んだ、という一点に集中して考えてみましょう。

システムの仕事は**「15:00の時点で、まだ利用時間が終わっていない予約」**をすべて探し出すことです。

時間軸で見てみましょう。

```
時間軸:  --|----------|----------|----------|----------|--
        11:00      12:00      13:00      14:00      15:00 (←ユーザーが選んだ時刻)
```

#### ケース1：Aさんが「14:00」に予約していた場合
-   Aさんの利用時間は `14:00` 〜 `17:00` です。
-   ユーザーが選んだ `15:00` は、この時間帯に**含まれています**。
-   → **この席はNG（予約不可）**

#### ケース2：Bさんが「12:30」に予約していた場合
-   Bさんの利用時間は `12:30` 〜 `15:30` です。
-   ユーザーが選んだ `15:00` は、この時間帯に**含まれています**。
-   → **この席もNG（予約不可）**

#### ケース3：Cさんが「11:30」に予約していた場合
-   Cさんの利用時間は `11:30` 〜 `14:30` です。
-   ユーザーが選んだ `15:00` は、この時間帯に**含まれていません**。
-   → **この席はOK（予約可能）**

### 法則性が見えてきた！

上の例から、**「ユーザーが選んだ時刻 `15:00`」** に利用中となる予約は、
**「`12:00` から `15:00` の間に始まった予約」** であることがわかります。

`12:00` というのは、`15:00` から `3時間` を引いた時刻です。

つまり、システムはデータベースに対してこう命令すればよいのです。

> **「`start_time` が【ユーザーが選んだ時刻 - 3時間】から【ユーザーが選んだ時刻】の間にある予約を、全部持ってきて！」**

これが、**「3時間引く」** の正体です。

## 映画館の例え

あなたは「15:00」に映画館に着きました。上映時間はすべて3時間です。
あなたは受付の人にこう聞きます。「今、上映中のスクリーンはどれですか？」

受付の人は、頭の中でこう考えます。
「3時間前、つまり**12:00以降に始まった映画**は、全部まだ終わってないな。12:00から15:00の間に始まった映画のリストを渡せばいいんだ」

この受付の人の思考こそが、今回の予約システムのロジックそのものです。

---

## まとめ

同じ「3時間」でも、視点と目的が全く違います。

-   **3時間足すのは…**
    -   **予約を入れる人**が「いつまで使えるか」を知るため。（未来を見る計算）

-   **3時間引くのは…**
    -   **システム**が「この時間は空いているか」を調べるために、過去の予約を逆算するため。（過去を振り返る計算）

この2つの視点を区別できれば、もう混乱することはありません。





変更点の解説
time_range = (start_time - 3.hours)..start_time ユーザーが選んだ時刻（start_time）から3時間前の時刻を計算し、.. を使って時間の「範囲」を作ります。 例えば start_time が 15:00 なら、12:00..15:00 という範囲オブジェクトが作られます。

start_time: time_range .where句にこの範囲オブジェクトを渡すことで、Active Record（Railsの機能）が賢く解釈し、SQLのBETWEEN句に変換してくれます。

これにより、データベースに対して「start_timeが12:00から15:00の間にある予約を探してください」という、まさに我々がやりたかった問い合わせが実行されるのです。

この修正で、3時間制を考慮した正しい空席チェックが実現します。
